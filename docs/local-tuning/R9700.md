# R9700 / Haswell DeepSeek tuning branch

This personal fork preserves experiments measured on one Radeon AI PRO R9700,
Xeon E5-2680 v3 (12 physical cores), 256 GB RAM in four DDR4-2133 channels,
and PCIe 3.0 x16. It is not an upstream release or a claim about other hardware.

## Source and attribution

The first commit imports Aaron Zhong's Strata PR #5765, head
`3852b6f8e3d7838cde06d22f81afb5c3027d3679`, retaining its original author.
The one-token AVX2 kernels retain GGML's arithmetic and first-use parity gate.
This fork changes selection to explicit `STRATA_CPU_IQ_OWN1=1`.

The single-NUMA CPU pipeline is adapted from Project Maya PR #928, head
`9ddb86cf7479a08d2ac129b8d835e7a2644f840c`, under its MIT license. It retains
original quantizers and row kernels. Multi-NUMA systems take the original path.

## Build this fork

With a working ROCm SDK in `ROCM_PATH`, use a separate build directory:

```sh
cmake -S . -B build-r9700 -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DSTRATA_ENABLE_CUDA=OFF -DSTRATA_ENABLE_HIP=ON \
  -DSTRATA_BUILD_DSV41=ON -DSTRATA_BUILD_IQ_FLOW_TEST=ON \
  -DCMAKE_HIP_ARCHITECTURES=gfx1201 -DGPU_TARGETS=gfx1201 \
  -DCMAKE_PREFIX_PATH="$ROCM_PATH" \
  -DCMAKE_HIP_COMPILER="$ROCM_PATH/llvm/bin/clang++"
cmake --build build-r9700 --target strata-dsv41 ds4_iq_flow_test --parallel 2
./build-r9700/ds4_iq_flow_test
```

Point the serving configuration's `exe` at this build's `strata-dsv41` and enable
only the desired flags below. The release downloader still installs upstream
engines. Model files and credentials stay outside this repository.

## Opt-in settings

| Variable | Purpose | Default |
| --- | --- | --- |
| `STRATA_CPU_IQ_OWN1=1` | Exact AVX2 singleton rows on supported CPUs | Off in this fork |
| `STRATA_DS4_IQ_FLOW=1` | Pipeline quantization, gate/up, hidden quantization and down work | Off |
| `STRATA_DS4_IQ_FLOW_CHECK=1` | Recompute and compare the reference pipeline; diagnostic overhead | Off |
| `STRATA_DS4_BORROW_ALIGN=256` | Round borrowed arena capacity; actual input row count is unchanged | Original capacity |
| `STRATA_DS4_PREFILL_HEAT_FREEZE=1` | Keep prompt chunks from changing cache heat; routing/profile counts retained | Off |
| `STRATA_DS4_PREFILL_CACHE_DECAY` | Prompt-only heat multiplier | Existing decode multiplier |
| `STRATA_DS4_STREAM_WIN_OWN_POLICY=1` | Experimental window-specific streaming policy | Off; not adopted |
| `STRATA_DS4_PHASE_LOG=1` | Raw overlapping decode timers and singleton execution counts | Off |

The profiler collector also fixes a six-element local array indexed by chunk
stages through ten. The corrected collector uses sixteen elements, validates
stage indices, and accumulates all eleven chunk stages. This fixes a reproduced
CPU-side memory error; it is not a performance optimization.

Do not add CPU, head, verification and GPU timers together: they overlap.
The older chunk stage named `q_b+rope` also includes preceding slab output
projections; it does not isolate weight conversion or RoPE.

## Measured results and limits

The retained engine was built from upstream base
`dbb2d168cffa8cf793d9325358809d5263c7c6b0` plus the private source experiments.
Its SHA256 was `6e2eb63293d2e7211f6762404b79e25a983cc52a2216a72b8537c9e35df2fb17`.
It is not the hash of a new clean build of this branch. The combined branch adds
an already-tested profiler correction and makes singleton selection opt-in.

ISTA 2.25 weights, own IQ4_NL Engram, all six experts, compact IQ2_XXS DSpark
expert tensors with unchanged dense drafter tensors, confidence 0.65, 12 CPU
workers, 32,768-token prompt chunks, 2,048 MiB GPU reserve, context 98,304,
full **unpinned** CPU expert RAM copies, borrowed arena alignment 256,
CPU pipeline and prompt heat freeze enabled. No full-model HIP registration.
Conversation-slot and shared-prefix retention were disabled for these fresh
benchmark requests; ordinary warmup continuation reuse remained available.

| Fixture | Fresh prompt tokens | Prefill tok/s (two runs) | Decode tok/s (two runs) |
| --- | --- | --- | --- |
| 20K | 19,750 | 840.9 / 857.8 | 32.1 / 34.3 |
| 80K | 77,786 | 1,095.6 / 1,096.3 | 33.7 / 33.0 |

Each size used three warmups, a 60-second quiet gate and two fresh measured
requests, temperature zero, maximum 4,096 generated tokens. Every generated
function passed 500 random and four invalid-input cases. Both 20K answers had
incorrect example assertions; both complete 80K answers passed. The 35 decode
and 1,000 prefill target is **not achieved** across both sizes.

Passed before packaging: 24 singleton-dispatch full-pipeline type/window cases;
336 extended CPU-pipeline cases (including windows 8/16, aliasing and final
slot 127); 8,408 real-model reference-checked pipeline calls; full measured
20K/80K cohorts without GPU fault or borrowed-expert restoration mismatch.
Profiler correction: extracted collector sanitizer check and HIP 20K diagnostic.

The clean combined fork HIP build subsequently passed on the same R9700 toolchain.
Its CPU check passed 336 extended pipeline cases with singleton selection off,
then 336 with it on. All 24 format/window full-pipeline checks also passed with
positive singleton execution for types16/17. See
[fork-build-validation.json](fork-build-validation.json). The rebuilt binary
SHA256 is `392777fa94661a57c68e0ceb636074093d05bd7f539701e37e5691162ddc71cf`.
This rebuild was not run through a new full-model performance cohort.

Not established: CUDA/SYCL builds of this fork, multi-NUMA performance, full
256K prompt correctness/performance, general-workload speedup, or 35 tok/s.
The separate paired-row prototype and IQ2_S candidate are not adopted here.

The later personal server uses 262,144 context, four RAM conversation slots,
two shared-prefix starts and private cache paths. Repeated/interleaved requests
reused 1,145 of 1,146 tokens; shared-prefix reuse was 1,138 tokens. These are
functional cache checks, not a rerun of the performance cohort. Generic server
`conversation_cache.enabled` does not describe these DeepSeek environment
controls. Available disk space must exceed the engine's 8 GB spill safeguard.

## Transfer and RAM accounting

`tools/tuning/hip_transfer_monitor.cpp` is a diagnostic LD_PRELOAD shim. It counts
HIP copy API payload and large CPU writes into mapped staging allocations. It
does not measure PCIe packets, all direct GPU reads, or physical DRAM traffic.
Use a private `STRATA_TRANSFER_COUNTER_FILE`; do not preload it globally.
Read a v2 snapshot with `python tools/tuning/read_transfer_counters.py FILE`.
Keep per-field deltas within one process lifetime; nonzero range overflow means
staging accounting is incomplete.
Its executable allowlist includes `strata-dsv41`, `maya-ds4` and
`strata-transfer-probe`. Inspect the source before building or interpreting it.

Measured H2D bandwidth: 13.818 GB/s. Measured sequential RAM read bandwidth:
58.885 GB/s with twelve workers. An 80K decode planning proxy was 0.80–0.81 GB
per generated token (logical expert weights plus three times staging). This is
not physical traffic or a rigorous bound. DRAM counters were not collected.

Holding other costs fixed, serial-copy halving gives an illustrative PCIe 4.0
result of 37.14–37.98 decode tok/s from the measured 33.35 average. Overlap and
workload changes prevent interpreting this as an upgrade forecast.

Assuming the same channel efficiency, DDR4-2666 with 4/6/8 populated channels
would deliver about 73.6/110.4/147.2 GB/s. If, hypothetically, RAM service were
25% of decode wall time, the corresponding sensitivity is 35.1/37.8/39.2 tok/s.
That 25% is unmeasured. Do not multiply CPU, PCIe and RAM gains together.
There is no evidence that eight channels are necessary merely to reach 35.

## Reproduction and carry-over to Unsloth/Maya

Build the CPU check with `-DSTRATA_BUILD_IQ_FLOW_TEST=ON`, then run
`ds4_iq_flow_test`. Run `ds4_gg_bench --expert --type TYPE --nt N --threads 12
--mb 64 --reps 1 --exact` for types 16/17/18/22 and windows 1 through 6,
with `STRATA_CPU_IQ_OWN1=0` and `1`. Actual branch execution must be verified;
a symbol present in a binary alone is insufficient. Use a clean build folder.

For Unsloth UD-IQ3_XXS, retain its own Q6_K Engram and all six experts. Copy
ideas selectively: its formats, resident expert count, VRAM needs and cache
behavior differ. Begin with an unchanged same-day 20K/80K baseline using the
original fixtures and three warmups/two fresh requests/quiet gate. Verify zero
cached prompt tokens and complete generated answers. Record per-run prefill
**tokens/s**, decode, copy payload, power, swap, RAM availability and failures.
Only then vary one setting per same-binary comparison. Use isolated calibration
and expert-profile copies, preserve negative results, avoid concurrent builds
or bandwidth probes during timed requests, and disable core dumps for probes.

Start with unpinned full CPU expert RAM copies, physical-core workers, measured
GPU reserve/borrowed-arena capacity and safe chunk sizes. Then investigate the
native IQ3 kernels, CPU pipeline, prompt cache heat, GPU expert residency,
streaming calibration and optional speculation. Do not assume the ISTA-specific
singleton IQ2 gain applies to IQ3. Do not mix Engrams or silently change weights.
